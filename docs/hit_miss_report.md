# Hit/miss report and AMAT analysis

## Objective and baseline

This study evaluates the repository's direct-mapped cache using reproducible memory-access traces. The baseline is a 32-bit address, 1 KiB cache, 16-byte block, 64 cache lines, four 32-bit words per block and `MEM_LATENCY=4`. The design is blocking and read-only for the baseline experiments.

## Address mapping and controller timing

For the baseline, the address is divided into a 22-bit tag, 6-bit index and 4-bit block offset. The index selects one of 64 lines; the tag identifies the memory block occupying that line; the offset selects one of four words. The two least-significant byte-address bits are ignored because accesses are word-aligned. The valid bit prevents uninitialised tag RAM contents from creating false hits.

M1's FSM answers a hit in one cycle. A miss fetches four words, each costing `MEM_LATENCY + 1` cycles, then uses one miss-detection cycle and one response cycle. Thus end-to-end miss latency is `4 × (4 + 1) + 2 = 22` cycles. Since hit time is one cycle, the miss penalty used by AMAT is 21 cycles.

## Trace workloads

Seven deterministic 4096-access read-only traces are committed: sequential, uniform random, repeated 512-byte loop, phased stride, row-major 64×64 matrix, column-major traversal of the same matrix, and mixed hot-set/random traffic. All addresses are word-aligned and within the 256 KiB memory model. The generator uses a fixed seed. The row-major and column-major traces visit the same complete set of 4096 words; only traversal order changes.

## Reference-model results

The following values were generated by `python3 analysis/analyze.py --no-sweep` using the Python reference model at 1 KiB / 16 B / `MEM_LATENCY=4`. They are **not RTL simulation measurements**.

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Sequential | 4096 | 3072 | 1024 | 75.00% | 1024 | 0 | 0 | 6.250 |
| Random | 4096 | 19 | 4077 | 0.46% | 3616 | 2 | 459 | 21.903 |
| Loop | 4096 | 4064 | 32 | 99.22% | 32 | 0 | 0 | 1.164 |
| Stride | 4096 | 0 | 4096 | 0.00% | 2390 | 1364 | 342 | 22.000 |
| Matrix row | 4096 | 3072 | 1024 | 75.00% | 1024 | 0 | 0 | 6.250 |
| Matrix column | 4096 | 0 | 4096 | 0.00% | 1024 | 3072 | 0 | 22.000 |
| Mixed | 4096 | 3253 | 843 | 79.42% | 618 | 217 | 8 | 5.322 |

The repeated loop fits in the cache and has a high hit ratio after compulsory fills. Sequential and row-major workloads benefit from four-word spatial reuse. The column-major trace suffers because the 256-byte row stride maps different row blocks onto competing direct-mapped indices. The stride trace contains both cold/capacity effects and a deliberate same-index ping-pong phase.

## AMAT calculation

`AMAT = hit_time + miss_rate × miss_penalty`

For this controller, `hit_time = 1` and `miss_penalty = 21` cycles. For example, sequential traffic has a 25% miss ratio:

`AMAT = 1 + 0.25 × 21 = 6.25 cycles`.

The analyser also calculates measured average latency as the mean of per-access latency. For the deterministic blocking reference model, it matches formula AMAT exactly. RTL mode separately checks every RTL CSV row against the reference before calculating measured metrics.

## Parameter sweep and interpretation

The script sweeps cache capacities 512 B, 1 KiB, 2 KiB and 4 KiB against block sizes 8 B, 16 B, 32 B and 64 B for all seven workloads. It emits CSV tables and plots for hit ratio versus block size, hit ratio versus cache size, AMAT versus block size and per-workload hit ratio. Larger blocks can improve spatial reuse but increase miss service time; larger caches reduce eviction pressure but consume more storage.

## Evidence boundary and limitations

The table above is reference-model output. The repository's M4 `make test` target is the required RTL verification route; it runs directed tests and each trace through the Verilog testbench and compares hit/miss, returned data and latency with the golden model. No RTL result should be claimed until those runs have actually completed successfully. Synthesis metrics must come from M3's `synth/` scripts and `docs/synthesis.md`, not estimates in this report.

The current experiment is read-only, as defined in `plan.md`. Future extensions include set associativity, alternative replacement policies, write-back/write-allocate and application-derived traces.
