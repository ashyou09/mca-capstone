# Memory-access traces

Owner: M5 — trace generation and architectural analysis.

The trace format follows `plan.md` §4.4 exactly: each line contains a hexadecimal operation and a hexadecimal byte address. `0` means read. All addresses are 32-bit, word-aligned, and within `0x00000000..0x0003FFFF`. The baseline workload is read-only, as required by the frozen project scope.

Regenerate the committed workload set with:

```sh
python3 traces/gen_traces.py --count 4096 --seed 20261116
```

The fixed seed makes the random and mixed traces reproducible. The default count is 4096 so both 64×64 matrix traversals visit the same complete set of elements before their order is compared. The generator accepts 4096–10000 accesses per trace.

## Workload design

| Trace | Pattern | Locality being examined | Expected behaviour at 1 KiB / 16 B |
|---|---|---|---|
| `seq.trace` | Consecutive 32-bit words | Spatial locality | One compulsory miss followed by three hits for each new 16-byte line; 75% hit ratio for this trace length |
| `random.trace` | Uniform word addresses across 256 KiB | Weak spatial and temporal locality | Very low hit ratio; larger caches may help modestly |
| `loop.trace` | Repeated shuffled 512-byte working set | Temporal locality | Working set occupies 32 cache lines and fits in 64 lines; high steady-state hit ratio |
| `stride.trace` | 16-byte phase, 64-byte phase, then alternating addresses `0x30000` and `0x30400` | Spatial gaps and direct-map conflicts | The final two addresses are 1 KiB apart, so they have the same index and different tags. They fit in the 64-line fully associative shadow, but cannot coexist in the same direct-mapped line |
| `matrix_row.trace` | 64×64 32-bit matrix, row-major | Spatial locality | Consecutive words within a row share cache blocks |
| `matrix_col.trace` | Same 64×64 matrix, column-major | Same data, different access order | With a 256-byte row stride, rows compete for a subset of direct-mapped indices; the equal-capacity fully associative shadow distinguishes these conflict misses |
| `mixed.trace` | 85% accesses to a 96-word hot set, 15% uniform random | Mixed temporal locality and cold traffic | Most hot-set blocks fit, but random accesses can evict lines |

The values in the last column are workload hypotheses derived from the address patterns, not values hard-coded into the analyser. The committed reference-model summary is generated by `make analysis` and is explicitly labelled as a Python model result.

## Validation rules

The generator creates read operations only, uses a fixed PRNG, emits no Verilog-incompatible comment lines, and writes each trace through a temporary file before replacing the destination. The analyser independently checks operation type, alignment, address range, and non-empty input. RTL verification remains M4's responsibility: run `make test` to send the traces through the RTL testbench and compare each access with `analysis/golden_model.py`.
