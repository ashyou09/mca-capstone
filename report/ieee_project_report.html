Abstract—This Phase I report presents the microarchitectural design, synthesizable Verilog RTL implementation, and initial hardware verification of a direct-mapped cache controller. Targeting the memory latency wall in digital processor systems, the proposed solution implements a 1 KiB cache with 16-byte blocks, 64 lines, and 32-bit word-aligned addressing. The design partitions the memory hierarchy into modular building blocks: an address decoder, a 64×22-bit Tag RAM, a 64×1-bit Valid RAM with single-cycle synchronous clear, a 64×128-bit Data RAM with word-granular write enables, a combinational Tag Comparator, and a 4-state Mealy/Moore Controller FSM. The controller guarantees a single-cycle read hit latency and coordinates a 4-word refill handshake with a behavioral main memory model, incurring a deterministic 22-cycle miss latency. Prototype functionality is verified through a 10-scenario directed testbench with 146 runtime assertions alongside an access-by-access trace co-simulation against a bit-accurate Python golden reference model. Deliberate fault-injection mutations confirm testbench rigor. All five team members have authored distinct modules and verified deliverables as detailed in this submission.
Index Terms—Direct-mapped cache, Finite State Machine (FSM), Hardware verification, Cache controller, Computer architecture, Verilog HDL, Phase I.

I. Introduction

In modern computer systems, the performance gap between processor execution frequency and main memory (DRAM) access latency constitutes one of the most critical bottlenecks in hardware design. A memory request issued to un-cached storage typically incurs dozens to hundreds of clock cycles of execution stall. Cache memory bridges this performance disparity by exploiting two fundamental principles of locality: temporal locality (reusing recently accessed data) and spatial locality (accessing adjacent memory words within a block).

For Phase I of this capstone project, our group has designed, implemented, and verified a parameterized direct-mapped cache controller in synthesizable Verilog. The primary objectives are: (1) realize a single-cycle read hit response; (2) ensure single-cycle synchronous reset invalidation of all cache lines; (3) orchestrate a cycle-accurate 4-beat burst refill protocol with main memory; and (4) demonstrate complete prototype verification with 100% assertion pass rates.

II. Literature Review

The foundational concept of cache storage was introduced by Maurice Wilkes in 1965 [1], who proposed "slave memories" to automatically manage high-speed storage buffers transparently to programmer software. In his landmark survey, Alan Jay Smith [2] comprehensively categorized cache placement policies, line replacement heuristics, and write strategies, detailing the trade-offs of direct mapping versus set associativity.

Direct mapping provides minimal lookup latency and zero placement search logic because every physical address maps to exactly one predetermined line index. However, direct mapping introduces vulnerability to conflict misses, which occur when distinct memory blocks contend for the same cache line. Mark D. Hill and A. J. Smith [3] formalized the foundational "Three-C" taxonomy:

  • Compulsory (Cold) Misses: Unavoidable first accesses to a block.
  • Capacity Misses: Misses due to finite cache size, occurring even in a fully associative cache of identical capacity.
  • Conflict Misses: Misses arising from mapping collisions within the same line index, avoidable through associativity.

To reduce conflict penalties without compromising single-cycle hit critical paths, N. P. Jouppi [4] analyzed direct-mapped conflict behavior and introduced victim caches. In contemporary architecture textbooks, Hennessy and Patterson [5] established the quantitative framework governing cache design, defining Average Memory Access Time (AMAT) as:

ext{AMAT} = ext{Hit Time} + ( ext{Miss Rate} imes ext{Miss Penalty}) (1)

In hardware FPGA implementations, memory mapping is further constrained by primitive architectures: synchronous Block RAMs (BRAM) versus asynchronous distributed SelectRAM (LUTRAM) [6]. A one-cycle hit direct-mapped cache requires asynchronous read capabilities, dictating distributed LUTRAM allocation.

III. Proposed Solution & Architecture

A. Baseline System Parameters

The proposed cache controller interfaces a processor core issuing 32-bit word-aligned memory requests with a main memory model possessing configurable access latency (MEM_LATENCY = 4 cycles per word). The baseline configuration specifies:

  • Address Width ($ADDR\_W$): 32 bits.
  • Cache Capacity ($C$): 1024 Bytes (1 KiB).
  • Block Size ($B$): 16 Bytes (4 words of 32 bits each).
  • Number of Lines ($N$): $N = C / B = 1024 / 16 = 64$ lines.
Fig. 1. Microarchitecture block diagram of the direct-mapped cache controller, showing CPU interface, address decoder, storage arrays, tag comparator, FSM controller, and memory interface.

B. Address Decomposition

The 32-bit CPU byte address is decomposed into three orthogonal fields using parameterized Verilog $clog2 functions:

ext{Offset Width} = \log_2(16) = 4 ext{ bits } (addr[3:0]) (2)
ext{Index Width} = \log_2(64) = 6 ext{ bits } (addr[9:4]) (3)
ext{Tag Width} = 32 - 6 - 4 = 22 ext{ bits } (addr[31:10]) (4)

Within the 4-bit offset field, bits [3:2] yield the 2-bit word select (word_sel) selecting one of four 32-bit words delivered to the processor, while bits [1:0] are ignored for word-aligned accesses.

C. Storage Datapath Modules

Valid RAM (valid_ram.v): Designed as a flat 64-bit register vector rather than an inferred memory array. This allows all 64 valid bits to be cleared to zero synchronously in exactly one clock cycle upon assertion of active-low rst_n, ensuring no uninitialized tag can cause false hits.

Data RAM (data_ram.v): Employs word-granular write enables (w_word_sel). During memory refills, words are written individually upon arrival of mem_ack without corrupting neighboring words within the 128-bit cache line.

Tag Comparator (tag_comparator.v): Evaluates hit = valid & (stored_tag == requested_tag). If valid is deasserted, a miss is guaranteed.

D. Cache Controller FSM

The controller coordinates cache lookups and memory refill transactions through four operational states:

  1. S_IDLE: Monitors cpu_valid. Because RAM lookups and tag comparison are combinational, a hit is resolved in the arrival cycle. The controller asserts cpu_ready and stat_hit in cycle 1, providing single-cycle hit latency. On a miss, it pulses stat_miss and advances to S_REFILL.
  2. S_REFILL: Issues mem_req to main memory for four consecutive words starting at the block-aligned base address. Memory asserts mem_ack after MEM_LATENCY cycles per beat. On the fourth word ($word\_cnt = 3$), the controller asserts tag_we and valid_we, committing the line, and advances to S_RESPOND.
  3. S_RESPOND: The complete block is now cached. The controller pulses cpu_ready, delivering the requested word, and returns to S_IDLE.
  4. S_WRITE: Supported for write-through, no-write-allocate transactions when WRITE_SUPPORT=1.

E. Miss Latency Formulation

For $W=4$ words per block and memory latency $L=4$ cycles, end-to-end miss service latency is formulated as:

ext{Miss Latency} = W imes (L + 1) + 2 = 4 imes (4 + 1) + 2 = 22 ext{ cycles} (5)
ext{Miss Penalty} = ext{Miss Latency} - ext{Hit Time} = 22 - 1 = 21 ext{ cycles} (6)

V. Prototype Progress & Validation

A. Directed Hardware Testbench

The directed testbench (tb_cache_directed.v) executes 10 comprehensive verification scenarios:

  • TC-01 (Reset Invalidation): Read to address 0x00000000 post-reset reports MISS despite tag match, confirming valid bit gating.
  • TC-02 (Temporal Locality): Immediate re-read of 0x00000000 reports HIT with 1-cycle latency.
  • TC-03 (Spatial Locality): Consecutive reads to 0x04, 0x08, and 0x0C report HITs, verifying 16-byte block refill.
  • TC-05 (Conflict Misses): Alternating reads between addresses 0x2010 and 0x2410 (same index 1, tags 8 and 9) yield 100% conflict misses.
  • TC-08 (Mid-Test Reset): Pulsing synchronous reset during active refill purges all valid bits and resets counters.

All 146 directed assertions pass with 0 errors.

B. Trace Co-Simulation Results

Seven deterministic 4096-access workloads were evaluated against the Python golden model. The Repeated Loop workload achieves a 99.22% hit ratio (AMAT 1.164 cycles) due to temporal locality. Sequential and Row-Major Matrix traversals achieve exactly 75.00% hit ratio (AMAT 6.25 cycles), matching the theoretical $1 - (1/4)$ spatial reuse boundary. The Column-Major Matrix traversal yields 0.00% hits, demonstrating direct-mapped conflict thrashing.

Fig. 4. AMAT sensitivity across block sizes (8 B to 64 B), illustrating the architectural trade-off between spatial reuse and increasing miss transfer duration.

C. FPGA Synthesis

Synthesis targeting Xilinx 7-series yields 312 logic LUTs, 150 distributed RAM primitives (RAM64X1S), 133 flip-flops, and 0 Block RAMs, confirming that asynchronous reads map to distributed RAM. Static timing on Lattice iCE40 reports an Fmax of 83.15 MHz.
